# CAN LAB 项目展台

入口为仓库根目录的[index.html](../index.html)，采用原生HTML、CSS和JavaScript，不需要npm安装、打包或新增后端。使用已有项目Python启动：

```powershell
Set-Location 'C:\Users\Livio\Desktop\robot_can'
& '.\.venv\Scripts\python.exe' -m http.server 8766 --bind 127.0.0.1
```

访问 http://127.0.0.1:8766/ 。自行启动的前台服务可用Ctrl+C停止。前端的播放、筛选与导出均使用已保存的数据，不会执行训练或控制机器人。

## 建议展示顺序

1. 系统总览默认Full＋v5，说明世界模型与恢复监督的独立作用；切换BC＋v5，解释其两条件综合任务成功率最高，但不能将这一结论泛化至每个单独条件。
2. 对照实验切换干净、噪声0.05及联合条件；再看任务成功率与20步稳定性诊断。预算候选默认隐藏，开启后以斜纹和“未采用”标识展示。
3. 真实轨迹默认选Full seed17的救回案例demo_22000011。点击阶段条的“试抬确认”或“搬运”，查看在途命令、本步提交、加噪后实际执行及候选评分。切到同起点无恢复，对照302步完成与400步未完成。
4. 查看85步常规成功和两次尝试后仍失败的案例，区分策略本身的能力、恢复作用和失败边界。可逐步、拖动、倍速播放和导出当前回合JSON。
5. 点击模型与控制模块，再进入13页Word详细设计、完整报告或活动代码说明。右上角演示模式可隐藏侧栏，适合投屏。

## 内容与来源

- 正式展示为Full＋冻结v5；BC＋v5为本批两条件综合任务成功率最高的正式对照，页面不宣称Full全面最优。
- 统计只来自2026-10-22确认批次。12个恢复因素单元共1440次执行，另240次为新BC观测语义确认；独立起点始终为60个。
- 回放为3个事后选例、6条同起点配对轨迹，共1672个逐控制步。位置来自state_before，成功标记来自success_after；nextPhase是recovery.mode，即本步生成动作的阶段，不是next_mode。
- 图中淡线表示本回合已记录的完整轨迹，亮线表示已播放部分。容器轮廓只作位置参考；二维回放不是实时仿真或预测轨迹动画。
- 影像弹窗明确为10月12日无恢复的BC／Full／Plain对照；场景图为render_probe_visual.png静帧。均不冒充10月22日Full＋v5确认视频。
- 计算P95由正式v5逐控制日志重新汇总，含观测、BC、可选WM与恢复；物理推进与日志不在计时内。

## 文件与更新

| 文件 | 用途 |
|---|---|
| ../index.html | 页面结构与说明 |
| styles.css | 响应式布局与视觉样式 |
| app.js | 统计切换、画布、回放、导出及模块交互 |
| data.js | 小于500 KiB的展示数据，直接在浏览器解包，不下载整批原始轨迹 |
| build_data.py | 仅用Python标准库从冻结文件构建展示副本 |
| data_manifest.json | 输入SHA、字段语义、量化精度与生成记录 |

需要重建展示数据时，在根目录运行：

```powershell
& '.\.venv\Scripts\python.exe' -B -X utf8 web/build_data.py
```

构建器只重写web/data.js及web/data_manifest.json，不修改原始输入。坐标和动作保留6位小数，评分保留8位；显示副本不用于重算研究结论。原始完整精度日志仍可由回放区链接访问。

本次通过HTTP本地服务完成浏览器验证；浏览器工具不允许file协议，因此未对双击文件的离线浏览作实测承诺。浏览器检查与截图见[前端交付记录](../reproduction/frontend_showcase_20261028_01/README.md)。
