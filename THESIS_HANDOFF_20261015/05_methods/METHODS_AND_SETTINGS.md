# 方法、变量与实验设置写作资料

这是方法核对笔记，不是论文正文。来源是迁移包 `04_snapshot/` 下的原代码、配置与冻结协议；不新增实验。

## 1. 任务与输入

- 环境：robosuite 的 PickPlaceCan，Panda，OSC_POSE，底层 MuJoCo。公开 Can PH 低维示范来自 robomimic；原始 HDF5、下载来源 SHA 和划分均在 `04_snapshot/data/`。
- 总计 200 条父轨迹，train/dev/sealed_test 为 140/30/30。世界模型分支训练仅使用其中 20 条父轨迹的 160 组，开发为 8 条父轨迹的 64 组；不能将 140 条示范都写成世界模型训练父轨迹。
- 23 维观测含机器人和物体真值，不是纯视觉输入。`common.py::OBS_KEYS/pack_obs` 顺序如下（下标从 0 开始）：

| 下标切片 | 含义 | 数量 |
|---|---|---:|
| 0:3 | 末端世界位置 | 3 |
| 3:7 | 末端四元数 | 4 |
| 7:9 | 夹爪关节位置 | 2 |
| 9:12 | 物体相对末端位置 | 3 |
| 12:16 | 物体相对末端四元数 | 4 |
| 16:19 | 物体世界位置 | 3 |
| 19:23 | 物体世界四元数 | 4 |

`object` 中先相对位姿、后绝对位姿的顺序已对照本机 robosuite 1.5.1 `pick_place.py::_create_obj_sensors`。框架感知器是外部实现；相对位姿坐标约定按框架定义，勿擅自把四元数各维解释成欧拉角。外部源码核对位置见 `FRAMEWORK_SENSOR_ORDER.txt`。

动作是 7 维归一化控制输入：前三维位置控制，接下来三维姿态控制，最后一维夹爪。位置控制量还会经过 OSC 缩放，不能把动作值 0.05 直接写成末端位移 5 cm。

## 2. 延迟、噪声与滚动执行

固定延迟 D=2，以两个零动作初始化 FIFO。每步产生新动作、追加到队列、取队首动作执行。执行噪声加在执行动作前三个分量，标准差 0.05，之后限幅；不是观测噪声，也不是以米为单位的位置高斯噪声。相同起点与各方法使用配对噪声。

控制频率 20 Hz，每回合最多 400 控制步，名义 20 s。D=2 名义延迟 0.1 s；这不包括实际计算耗时，现有并行批量执行的 decision_ms 也不构成真机延迟基准。

BC 每次预测 H=8 个动作。固定 k=2 表示选取当前动作块第 3 个预测动作；其目的是利用动作块的时间索引补偿延迟，不是精确求得两步后真实状态，也不是实验中偷看未来。默认四个候选是 k=0、1、2、3。

每个候选的想象序列 = 真实待执行队列前缀 + 重复该候选的当前动作，截取总 H=8 步。真实部署只提交一个动作，下一次观测后重新规划；不能写成一次执行整段八步动作块。H 包括队列前缀，所以 D=2 时 H=1 看不到新候选生效。

## 4. 世界模型与评分

来源：`world_model.py`、`reproduction/multiseed_20261012_01/train_suite.py`。

状态先按训练观测均值与标准差归一化，标准差下限 0.02。GRUCell 隐层宽度 128，输入为当前递推状态与动作；隐状态经 MLP 预测残差，残差乘 0.1 后更新状态。Full 的评分头只读取预测状态，不直接读取 GRU 隐状态。预测和评分共同训练，未来状态不是仿真真值输入。

进展 p 与失抓风险 r 均为两路 logits 的 sigmoid。候选总分：

`S = p_H + 0.5 × mean_h(p_h) − 0.5 × max_h(r_h)`。

取最高分候选；相对固定 k=2 分数提升不足 0.02 时回退 k=2。门限是经验分数差，不是校准概率、置信区间或普遍安全保证。

训练进展真值来自仿真分阶段奖励最大值，成功时为 1；风险标签来自“分支初始已抓持、后续抓持奖励低于阈值且尚未成功”。它只表达定义下的失抓，不是总体任务失败概率。仿真奖励/成功/接触只在采集监督和事后诊断中使用；恢复控制器决策不读取这些诊断真值。

Full 损失：`L = L_state + L_progress + 0.5 L_risk + 0.2 L_rank`。状态项为按状态尺度归一化的预测 MSE，两个头为 BCE。排序项在同组候选对上按真值评分差方向采用 softplus，temperature=0.1；仅使用绝对真值分差大于 0.025 的候选对。

| 方法 | 差异 | 参数数量 |
|---|---|---:|
| Full | 状态预测、进展/风险、组内排序 | 87321 |
| Plain | 去排序项，其余对应配置相同 | 87321 |
| Direct | 当前状态与展平动作序列直接预测评分，无未来物理状态；宽度 251 做参数匹配 | 87364 |
| prediction_only | 只训练状态预测，评分头冻结且部署不用未训练评分头，采用物理代价 | 总参数 87321，训练参数量见实际 config |

三种子 17/23/41，共同数据、配对初始化与 minibatch、3000 次更新、batch=16、lr=0.0003。每 250 步保存 checkpoint，在固定开发集按 mean_regret 选最小值，平局取最早；prediction_only 则按开发归一化状态 MSE 选。不能将确认成功率作为选权重依据。

Full 原选中 step 分别 2750/1250/2750。10/14 的固定集复算只读取原权重，没有更换它们，也不是新增独立验证数据。

## 5. 共享恢复

来源：`reproduction/recovery_v5_20261012_01/recovery_controller.py`、`variants.py`、`study_plan.json`。同一恢复层用于 BC 与 Full；它是规则状态机，不训练新网络。

抓持观察结合夹爪间距、物体距离、最近 5 帧相对位置一致性、抬升高度及夹爪命令。默认距离阈值 0.09 m，相对位移容差 0.012 m，夹爪间距 (0.025,0.067) m，验证抬升 0.02 m；更完整参数见本目录 `EXTRACTED_SETTINGS.json` 和原 Config。不能把单次夹爪闭合等同于已可靠抓持。

阶段包括 NORMAL、RETRACT、ALIGN、DESCEND、CLOSE、TEST_LIFT、LIFT、CARRY、PLACE、RELEASE、RETREAT 及终止/耗尽状态，以实际代码字符串为准。检测持物/接近无进展、失抓和预算压力，最多两次尝试，总预算仍为 400 步，FIFO 不清空。

v5 相对 v4 加入 T（恢复时机与剩余预算安排）和 S（侧倒候选间隙筛选）；分别有 T-only、S-only 与组合对照。T 内部并没有逐项完全分离；新原生确认的时间救回主要支持剩余步数安排，不足以证明提前触发本身的独立贡献。S 的静态候选可行也不保证整个下降/闭合/搬运路径无碰撞或不滑移。

## 6. 指标定义，写作时须逐项区分

| 指标 | 定义/单位 | 不应混淆 |
|---|---|---|
| 成功率 | 400 步内框架成功条件；% | 不等于成功回合平均速度 |
| 归一化状态 MSE | 所有 23 维归一化误差平方均值 | 无物理长度单位，不等于位置 RMSE |
| 平均位置误差 | 对每点三维欧氏距离取平均，常以 mm 展示 | multiseed physical_prediction 是此口径 |
| 位置 RMSE | 按原 extensions 脚本定义先平方汇聚再开方，以 mm 展示 | 不与平均欧氏误差直接拼表排名 |
| mean_regret | 每组真实最优候选分数减所选候选真实分数，再求均值 | 局部候选评分指标，不等于终局成功率 |
| 训练种子 SD | 三个模型的均值/成功率离散程度 | 不是起点抽样的 95% 置信区间 |
| 配对交叉 bootstrap | 同时按起点和训练种子重采样，保留比较配对 | 复用起点不变成额外独立样本 |
| 共同成功步数差 | 同一起点双方成功才取 Full−BC 的完成步数差 | 条件于成功，不能代表全体回合效率 |

## 7. 写作环境说明

原冻结 Python 3.10.9、torch 2.14.1+cu130、NumPy 1.26.4、robosuite 1.5.1、MuJoCo 3.3.0。它们来自已存快照，不表示本轮又验证新电脑 GPU 兼容性。写论文读表、看图、包校验和本地静态服务只需普通 Python 3 与浏览器；不用迁移 `.venv` 或重新训练。
