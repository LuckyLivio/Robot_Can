## 已确认的问题与处理

| 原图 | 问题 | 当前处理 |
|---|---|---|
| success_rate | 数字直接写在脚本中，来自早期 30 回合配置；k=1 标为 strongest，与后续锁定 k=2 的实验不一致；不能代表当前结果 | 从独立确认原始 JSON 重算 BC k=2 / Plain / Full；清楚标注 60 起点及三个种子 |
| ablation | 19、23、23、22 等成功数写死，仅单种子、旧配置；完整 WM 与 Plain 持平也不能证明排序增益 | 改读三种子公平开发集，保留 Full 不占优的负结果，增加已有的仅预测、无风险评分和无门控对照 |
| paired_clean / paired_noise005 | 读取旧 k=1 与旧 WM，缺乏两侧起点集合一致性断言；这些历史结果不能自动代表新版 | 采用冻结确认的 BC k=2 与 Full；逐起点匹配，三个种子分别展示 |
| success_steps | 对各方法各自成功子集作箱线图，子集不同；不能据此直接判断同一任务谁更快 | 改为双方都成功的相同起点上逐回合差值，并保留全部点和样本数；仍有条件选择限制 |
| training_curves | 日志中的 step 为 250…3000，却画成 1…12 并标成 epoch；不同损失同轴，且只用了旧单模型 | 改为当前 Full 三种子真实 step、分面原始损失与开发集 regret；标出按开发集选中的 checkpoint |
| method_diagram | “安全 FIFO”混淆延迟队列与安全/恢复控制；“失败风险”比实际失抓标签更宽；执行箭头不清晰 | 按冻结评估实现画真实 FIFO 前缀、重复候选想象、k=2 回退和逐步闭环，明确不含恢复控制 |

旧图不等于所有历史数值算错：配对图确实读取旧结果，训练纵轴也确实来自旧日志。主要错误是版本过时、标注错误和比较口径不足。因此原图、旧脚本与改前文档均按字节归档，不能用新版图反过来改写旧实验。

Full 与 BC 的配对，类别依次为双方成功、仅 Full 成功、仅 BC 成功、双方失败：无噪声三个种子都是 [51,3,0,6]；噪声分别 [49,3,0,8]、[49,3,0,8]、[49,2,0,9]。成功步数交集每种子分别为 51 与 49 个起点。

原分析中 Full−BC 预先约定的条件等权联合差值为 +4.72 个百分点，配对交叉 bootstrap 区间 [0.56,10.28]；Full−Plain 为 +1.94，区间 [-0.56,6.11]。单个条件的 Full−BC 区间下界均为零。新版柱图不以三个种子点伪装置信区间，也不暗示 Full 对 Plain 有可靠提升。

开发集上 Full 的无噪声 / 噪声均值是 78.89% / 82.22%，Plain 是 80.00% / 84.44%。这与确认集不同，属于不同起点集合，不能删除或混入确认集以美化结论。

## 曲线应该如何解释

每 250 次优化器更新才记录一个点，12 个点覆盖 3,000 次更新。训练损失是当时随机批次值，不是 250 步平均值；起伏本身不是绘图错误。本次没有拟合出“持续下降”的曲线。开发集 regret 在相邻点的跳变也保留，因为候选排序及最佳候选选择是离散的；不能仅凭跳变断言训练异常或稳定收敛。

新版训练图使用 multiseed Full 权重的真实训练记录，不是把旧模型改个横轴后冒充新模型，也不是评分头校准的训练图。确认评估选择这些模型，后续恢复控制继续复用它们。图中不把 v5 恢复成功率当作世界模型本身的增益。

## 验证与保留

绘图时逐条验证 2,640 条已有记录（840 确认 + 1,800 开发）及全部汇总成功率；配对检查起点集合，无重复或缺失；训练点检查有限数值、递增 step、最终更新次数和 checkpoint 选择规则。7 张 PNG 均检查了可见排版，并同步输出 PDF；数据和源 SHA-256 见根 figures/figure_data.json。

只修改绘图脚本、根 figures、README 的图表/校验说明及 EVIDENCE_INDEX 中相应入口；没有修改训练与控制算法、模型权重、原始回合、前端或旧验证清单。原 14 张图和脚本在 before/，原始哈希在 before_manifest.json。当前校验入口为本目录 verify.py，结果保存为 verification.json。
