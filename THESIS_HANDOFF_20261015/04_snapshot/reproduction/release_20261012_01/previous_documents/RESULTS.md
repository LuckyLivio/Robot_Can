# 延迟补偿世界模型：冻结结果

更新时间：2026-10-09。结果来自 robosuite 1.5.1 PickPlaceCan / Can PH 的低维状态闭环仿真。这里的“视觉世界模型”尚未实现，当前报告的是视觉输入前的可复现实验闭环，用来先验证算法机制。

## 研究问题和方法

任务是在固定 FIFO 动作延迟 `D=2` 下完成抓取放置。BC 策略输出动作块，部署时构造 4 个时间偏移候选 `k∈{0,1,2,3}`。完整方法用 action-conditioned GRU 世界模型递归预测候选动作作用后的未来状态，再由进度头和失败风险头给候选打分；若最佳候选只比安全先验高不到 `δ=0.02`，则回退到安全先验。训练同时使用状态预测损失、进度/风险监督和同一状态下的候选排序损失。

固定偏移基线先在开发集扫描 `k=0..3`，再冻结最强的 `k=1` 作为封存测试主基线。这一步避免把较弱的固定偏移挑出来与世界模型比较。

## 主要闭环结果

| 方法 | 开发集（30） | 封存测试·干净（30） | 封存测试·位置噪声 σ=0.05（30） |
|---|---:|---:|---:|
| 普通 BC，`k=0` | 15/30 = 50.0% | 17/30 = 56.7% | 19/30 = 63.3% |
| 固定偏移 `k=0` | 15/30 = 50.0% | — | — |
| 固定偏移 `k=1`（开发集最强） | 24/30 = 80.0% | 21/30 = 70.0% | 19/30 = 63.3% |
| 固定偏移 `k=2` | 23/30 = 76.7% | 22/30 = 73.3% | 24/30 = 80.0% |
| 固定偏移 `k=3` | 21/30 = 70.0% | — | — |
| 完整 WM + 风险门控，回退 `k=1` | **25/30 = 83.3%** | **23/30 = 76.7%** | **23/30 = 76.7%** |

主结论是：在固定偏移已经很强的前提下，世界模型门控在封存测试集干净条件下多成功 2 个回合，在执行噪声下多成功 4 个回合。噪声条件更能体现世界模型的作用，因为候选动作的好坏不能只由固定时间偏移决定，需要依据当前状态预测风险。这个提升是中等幅度，不能夸大为所有条件下显著优越。

需要把比较规则写清楚：传统的延迟长度偏移 `k=2` 在这次噪声封存集上恰好达到 24/30，高于 WM 的 23/30；因此本文不声称 WM 击败每一种固定规则，而是先用开发集冻结 `k=1` 作为主要公平基线，再把 `k=2` 作为辅助诊断，证明收益来自状态依赖的候选筛选而不是挑选较弱基线。

成对比较也支持同一解释：干净测试集为 WM 独胜 3 回合、固定偏移独胜 1 回合；σ=0.05 为 WM 独胜 4 回合、固定偏移独胜 0 回合。相应图见 `figures/figure_paired_clean.png` 和 `figures/figure_paired_noise005.png`。

## 结构消融

预先声明的噪声封存测试条件下：

| 变体 | 说明 | 成功率 |
|---|---|---:|
| Shift `k=1` | 最强固定时间偏移先验 | 19/30 = 63.3% |
| 完整 WM + 门控 | 递归未来状态 + 排序损失 + 风险门控 | **23/30 = 76.7%** |
| Plain future | 去掉候选排序损失，保留未来状态预测 | 23/30 = 76.7% |
| Direct scorer | 只对当前状态直接评分，不递归预测未来状态 | 22/30 = 73.3% |

开发集的机制诊断更容易拉开差异：完整模型 25/30，plain 20/30，direct 21/30；完整模型还高于不门控版本的 20/30。封存集上 plain 与完整模型恰好相同，因此论文应报告这一事实，把排序损失解释为提高开发集候选辨别能力的机制，而不要宣称它已经在单个封存划分上显著改善泛化。

## 多种子与旧配置的处理

早期扩大训练示范数的三个模型在另一套 `k=2` 回退配置、σ=0.05 下得到 24/30、25/30、25/30。这组结果可放在附录作为训练规模/随机种子敏感性，但主表采用开发集冻结出的 `k=1` 强基线，避免混用配置。

早期曾测试过把延迟后的观测直接喂给 BC 的错误接口，结果变差；复核后确认问题是训练时队列为空而部署时队列非空造成的队列覆盖不足，并非“世界模型重复施加延迟”。该探索保存在 `queue_v2.py`，不作为正面结果。
