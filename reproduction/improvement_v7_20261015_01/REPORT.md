# v7 姿态重规划与未知可行性处理：结果与采用决定

2026-10-15。**实现和小测试/消融已完成；合用版未通过进入开发集的门槛，不替换主版本。** 未启动 240 回合开发测试，未做泛化训练，未写论文。旧文件、权重、结果和前端均保留。

## 1. 本轮做了什么

在新目录继承冻结 v6，增加两个可独立关闭的模块：

- **姿态重规划**：抓取前物体位移超过 15 mm 或轴向变化超过 20 度时，使旧计划失效；先收回，观察连续 4 帧稳定，再重新规划。罐体绕自身轴旋转不触发误报。最多接受 2 次重新规划，不增加原有 2 次抓取尝试和 400 步预算。
- **未知可行性处理**：现有直立/侧倒支持区域均无法识别时，进入 `POSE_WAIT`；每隔 5 步重新检查。40 步内仍未确认则进入高位 `POSE_BLOCKED`，不再默认沿旧抓取计划下降。

两项只使用已有状态观测、历史、固定目标与几何。未改 BC、世界模型权重、候选评分、环境成功标准或 D=2 延迟。控制仍为 20 Hz。可行性检查是现有局部几何近似，不能解释为完整机械臂碰撞或安全证明。

姿态单项在 6 个回合各接受了一次重规划；合用版在 5 个回合各接受了一次重规划。它们改变了恢复过程，但本批未救回原有失败。完整阶段和触发计数见 [pilot_b_mechanisms.json](analysis/pilot_b_mechanisms.json)。

## 3. 为什么增加保护后反而少成功一次

退步条件为 BC k=2、噪声 0.05、`regression_6000005 / demo_6000005`。这不是新的独立确认样本，而是此前已见过的保护案例。

- 第 121 步触发恢复。第 129 步罐体原点约为 `(0.2959, 0.3080, 0.9402)` m，竖直轴接近直立；地板为 0.8 m。物体已经位于当前支持区域之外，且高度不属于直立落地模型覆盖范围。
- v6 进行了两次对齐，各自超时，第 279 步进入 `EXHAUSTED` 并交回原策略；第 311 步由原环境判定成功。这是原策略接手后完成，不能记作已验证的恢复重抓成功：其 `verified_regrasps=0`。
- 未知单项和合用版在第 129 步转入等待；状态始终未进入已支持区域，第 169 步转入高位保持，直到第 400 步失败。

因此，不能简单说“区域判断错误”，也不能为了保住成功率把未知重新当成可行。当前局部规划确实没有覆盖这个状态；新方案只有停止/等待，缺少下一步可执行策略。此前基线的成功也不能证明那段运动平滑或无碰撞。

源记录：[v6](pilot_b/v6_regression_6000005/result.json)、[v7](pilot_b/v7_regression_6000005/result.json)。对应目录下有完整逐步轨迹。该案例已纳入保存动作的物理重演检查，结果一致。

## 4. 测试与完整性

| 检查 | 结果 |
|---|---|
| 关闭两项新开关与冻结 v6 比较 | 240 个记录回合、38,292 步；动作、诊断、事件完全一致 |
| 姿态改变、稳定后重规划、未知等待、旋转对称性、重规划次数上限 | 单元测试通过；包含诊断 JSON 可序列化检查 |
| 四路小测试的记录输入重演 | 148 回合、41,616 步；控制/FIFO/噪声/事件一致 |
| 新机制逐步检查 | 启用未知保护时，所有抓取下降及入口均已判定可行；启用姿态保护时，没有超过登记姿态变化阈值的旧计划下降 |
| 基线重复执行一致性 | 本轮 v6 的 37 回合、10,490 步与先前 v6 小测试逐项一致，耗时字段除外 |
| 保存动作的 MuJoCo 重演 | 16 回合、5,146 步；状态、阶段奖励、成功标记逐元素一致 |
| 旧文件保护 | 7,946 个登记文件 SHA-256 全部一致 |

上述机制检查针对抓取下降决策；高位保持控制在过冲后可能发出向下的位置修正，并不等于重新下降抓物。D=2 队列中此前已经提交的动作也不会被事后抹除。检查不构成所有连续时间状态的安全证明。

最初 `pilot_a` 因 `numpy.bool_` 诊断序列化中断。只修正了 Python 布尔转换并增加序列化测试，未调整控制阈值；随后在 `pilot_b` 全量重启。`pilot_a` 的源快照、部分日志和结果均保留，其中 16 个回合有完整摘要，但它不是完成的四路消融，不合并进 148 回合的主表。修订记录见 [revision_b.md](protocols/revision_b.md)。

物理重演是验证保存的动作，不是额外的独立实验。凭这些检查可以确认结果可追溯，不能把“校验通过”写成“效果提升”。

## 5. 当前优化进度

- **v6**：已修复特定恢复中的开度振荡和已判定无可行候选时的重复下降。已知诊断比 v5 多救回 2 个条件；开发集仍是 v5、v6 各 236/240，未通过净增成功的采用门槛，保留为候选版本。
- **v7 姿态单项**：逻辑与本批诊断可通过，但成功数未提高，尚无开发集结果。
- **v7 合用**：补上了未知分支，却造成一例退步，未通过预登记“保留全部 v6 成功”的门槛。**不进入开发集，不替换现用版本。**

项目并未达到“所有场景完美恢复”。当前可报告的是机制缺口、受控修复与清楚记录的负结果，不能声称世界模型的泛化已经改善。

## 6. 下一轮应如何缩小问题

先分别诊断 **贴壁侧倒、箱沿高位和超出工作区**，明确哪些状态有可靠的支撑面、抓取路径和机械臂可达性。不要统一放宽所有区域阈值，也不要在超时后直接取消保护。

在具有可验证路径的状态上，单独增加“撤离后重新定位/重新规划”的有界处理；无法建立可行路径时，继续承认失败。未知等待的退出策略应独立消融。先保留姿态重规划这个未造成已知退步的模块，再与退出策略组合，重新跑原 37 条件保护集，过门槛才冻结并进入 240 回合开发对照。

如果新增推移/扶正技能、扩大几何适用范围或给动作加平滑滤波，都已经超出本轮两项最小改动，需要独立记录和验证，不能事后沿用当前成功率。

## 7. 与前端“卡顿、抽搐”的关系

当前三栏视频是原始 BC/Full/Plain seed17，10 fps；恢复轨迹动画是 v4/v5，20 Hz 逐点显示。**都未接入 v6/v7，所以不能由当前网页观感判断本轮优化。** 原始失败轨迹也存在真实往返运动，不能全部用低帧率解释。

低帧率不改变仿真保存的成功率；真实振荡则限制“运动平滑、稳定、安全”等结论。建议后续用冻结动作导出逐控制步 20 fps 视频，明确版本和种子；显示插值必须标注并保留原始数据，不能用平滑图掩盖实际控制问题。
