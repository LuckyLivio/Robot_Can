# 恢复失败与开发泛化：最小改进方案

日期：2026-10-15。状态：**方案，尚未实施**。本次只读核查既有代码与证据，没有修改旧代码、权重、结果或论文资料，没有新增训练/推理/仿真。

## 一、目标与范围

先修复可定位的恢复控制缺口，再单独检查扩大数据覆盖是否改善世界模型泛化。候选评分体系、BC、世界模型网络、训练损失和优化器本轮保持现有配置。避免同时引入多个学习改动而无法解释结果。

建议实施目录为 `reproduction/improvement_v6_20261015_01/`，内部 recovery/、generalization/、protocols/、results/ 分开。模型与数据使用全新名称，旧文件按 SHA-256 冻结；检查新增代码关闭开关时能复现 v5。根目录旧脚本保持原路径。

本轮不承诺解决物体掉出台面的重新拾取，不新增推物/重定位技能，不扩大 400 步预算，不清空 D=2 队列，最多两次恢复尝试。静态手爪几何不覆盖整条机械臂，因此本方案不能宣称完整碰撞安全。

## 二、恢复侧仅改两项

### R1：夹爪实际开度与局部运动路径检查

现有 `v5/clearance.py::clearance_margin` 对单个姿态和指定开度检查几何余量。`plan_side_clearance` 搜索时使用固定 side_gap=0.056 m，但动作执行时实际间距可能更大；已知压力失败曾观测约 0.060 m。当前 upright corner 筛选也主要依赖二维终点余量。

新增 `recovery/clearance_guard.py`：复用 v5 手掌/手指几何和区域判定，检查“上方接近→下降→闭合→短距离试抬”的局部段，而不只看最终抓取姿态。使用当前观测开度、目标开度与过程中预计经过的开度包络，并加入依据已知开发轨迹测得的经验位姿/开度余量。特别注意张爪命令存在 D2 延迟，不能假定夹爪已达到目标间距。

控制侧同步做到“规划什么开度，执行什么开度”：在物体上方先预整形夹爪，按观测间距确认到位；下降过程中保持允许的开度。原 DESCEND 使用张开命令，不能一边按窄间距检查几何，一边继续把夹爪张到更大。具体开度反馈控制先做小测试，包含 D2 滞后、限幅和跟踪误差；无法达到允许范围则不进入下降。

路径用离散位姿采样做保守筛选，采样间隔和余量在小测试前锁定并记录。候选规则仍是已有限定高度/偏移/倾斜范围，不增加无界搜索。离散检查只能降低已知碰撞风险，不能证明连续路径无碰撞；接触仅作事后诊断，不作为控制输入。

### R2：没有可行候选就退出该下降计划，失败尝试不重复

现有 `plan_side_clearance` 在 options 为空时记录 feasible=False 后返回，主控制流程仍可能按旧姿态继续 DESCEND。`plan_guarded_corner` 无 options 时也直接返回。

新增 `recovery/recovery_controller.py`，以 v5 为基底，仅调整候选规划结果和 ALIGN/DESCEND/CLOSE/TEST_LIFT 附近的转换：

1. 规划结果显式区分可行、物体区域不适用、无候选、执行偏差过大；不混用“没有算出新方案”和“原方案可行”。
2. 无候选或关键执行检查不通过时，先沿受检退回段撤到上方，不直接重复原下降。第二次只能选其他经过检查的候选；用已失败候选/路径记录避免原地重试。
3. 物体明显移动时重新规划，不能对旧物体位置的候选继续执行；尝试记忆需与物体当前姿态关联，不能永久禁止后来变可行的方案。
4. 试抬期间持续观察相对位移、物体高度和开度。验证不稳定则撤回并消耗该次尝试，不能把短暂跟随当可靠搬运。
5. 如果没有其他可行候选，明确记录失败/退出。主动退出不是任务成功，成功率统计仍使用原环境终局条件。

保留 v5 已有抓持和失抓检测，先不另加更长等待、更多尝试或新运输轨迹。若上述两项不足以解决滑移，单独记录为下一阶段能力缺口。

## 三、泛化侧先只扩父轨迹覆盖

原世界模型训练来自 20 条父轨迹、160 组；开发来自 8 条父轨迹、64 组。现有训练器已会按开发 regret 保存最佳 checkpoint，因此机械地增加 early stopping 不能保证得到更好的已选模型。原来每条父轨迹组数也相近，不能把形式上的“父轨迹均衡采样”当成已经解决数据覆盖。

### G1：训练父轨迹 20→40，不跨划分

- 保留原 160 组，在原 train=140 条父轨迹中预先锁定另外 20 条，每条仍取 8 个锚点，目标合并为 320 组。
- 新父轨迹按固定种子与明确列表选择，不按旧确认成败挑选。所有新增父轨迹必须与 dev/sealed_test 隔离。
- 使用既有真实 FIFO、BC k=2 闭环锚点和完整历史恢复采集方法。先核对缓存、传感器刷新、正逆序分支与队列前缀的一致性。不得仅给旧 NPZ 加随机噪声冒充物理可行新数据。
- 如果已有额外分支完全满足本轮冻结的动作/恢复/标签语义，可先核验复用；否则只采缺少的新父轨迹。只有 source、shape、分区和重放检查通过的数据才能合并。

### G2：新增开发诊断父轨迹，保持选点规则可解释

- 原 8 条/64 组仍作为新模型的选点开发集，使用原 mean_regret 最小、平局最早的规则，先不同时改变选择目标。
- 从 dev 的其余父轨迹预先锁定另外 8 条/64 组，只在每个种子的 checkpoint 选好后评估，用于检查跨父轨迹泛化；不逐 checkpoint 查询它来调参。
- 这些是新增分支诊断父轨迹，不是全新原生终局确认起点；原 BC 或研究过程可能已经见过这些示范，不能称完全未接触测试集。

### G3：复用原训练器，先只训练 Full 三种子

`multiseed/train_suite.py` 已支持由 protocol 指定数据集、动态读取 n_groups。为新协议生成适配入口，直接复用其学习逻辑：Full，17/23/41，3000 更新，batch=16，lr=0.0003，宽度128，原损失与 Adam。无需重训 BC，也不必立即重训所有消融。

添加只读 `generalization/evaluate_fixed_sets.py`，报告完整固定训练集和选点开发集的状态预测、进展BCE、风险Brier、评分MAE、regret及逐父轨迹结果。额外开发集仅查询已选模型。

**比较时统一尺度。** 扩充数据后模型自己的 mean/scale 会改变，不能直接把各自 scale 下的归一化 MSE 相减，误判成泛化改善。跨模型使用同一冻结参考 scale（原训练数据尺度），同时报告物理位置误差；各自训练尺度 MSE 单列描述。均欧氏位置误差与 RMSE继续分开命名。

若只扩大数据没有改善，记录负结果并停止晋级。AdamW/评分头正则化可作为下一轮单独干预，本最小轮不同时加入，避免无法判断数据覆盖的贡献。

新增数据仍先采用与旧训练一致的 BC k=2 锚点分布，不自动覆盖 v6 恢复接管后的全部状态。应单列正常/恢复后状态的误差；若主要缺口来自恢复后的访问分布，下一轮另采对应状态分支，不能仅凭新增父轨迹就宣称已解决这种分布偏移。

## 四、验收顺序与建议门槛

这些是待执行前锁定的建议门槛，不是本次已达到的结果。不能看完测试后调低门槛。

### A. 小测试与恢复组件消融

使用已知开发/故障诊断案例，覆盖直立角落、源箱侧倒、目标箱窄格、无可行候选、抓起后滑移，以及既有成功案例。旧确认中已看过的失败可以用于诊断，但此后不再算独立确认。

四种配置：v5原版、R1-only、R2-only、R1+R2。小测试优先检查：关闭开关逐步复现v5、D2队列和400步/两次预算不变、开度包络与路径采样生效、无候选不重复下降、已有受保护成功案例不退步。任何一项不通过就不跑大批。

### B. 恢复开发集对照

仅把小测试选定的组合送入既有匹配开发起点：BC k=2 + 冻结 Full 三种子，两种噪声条件、30起点，共240个新执行回合。匹配旧v5开发记录可以在输入与执行语义确认一致后复用，不为凑样本重跑。

建议晋级要求：相对v5净成功数增加，至少救回一个不同的旧失败起点；保护案例无退步；新失败不能被只报告“碰撞减少”掩盖。按起点列救回/退步，原生和人工压力测试分开。若只减少碰撞却让成功率下降，视为未通过。

### C. 泛化开发验收

先比较冻结旧Full与新增数据Full的三个种子，查看原64组与额外64组：共同参考尺度MSE、末端/物体位置误差、score MAE、risk Brier和regret。建议至少2/3种子呈一致方向，不能只选一个最好种子；位置误差和评分不允许为追求一个MSE数值出现明显恶化。

可预先采用共同参考MSE均值至少改善5%、物理位置与评分误差均值不恶化超过5%的开发门槛；百分比是本轮建议，须在执行前写入协议，不能当总体显著性保证。报告按父轨迹汇总和配对区间，不把128组算成128条独立轨迹。

通过离线门槛后，在已经固定的v6恢复下比较旧/新Full，3种子×两条件×30起点=180个新执行回合；旧Full+v6的对应数据复用恢复开发阶段。成功率不能明显退化，且不能仅用预测误差改善宣称闭环收益。

### D. 最后一次冻结后的新起点确认

两条线通过开发门槛后，再冻结新控制器与新权重、预锁另一批60个全新原生起点，比较四组：

| 组 | 用途 |
|---|---|
| 固定BC + v5 | 旧恢复参考 |
| 固定BC + v6 | 在相同BC下检验恢复改变 |
| 旧Full三种子 + v6 | 新恢复下的旧世界模型参考 |
| 新Full三种子 + v6 | 隔离训练数据扩充的增量 |

两种执行条件下总计 `(1+1+3+3)×2×60=960` 回合，仍只有60个配对起点。该最小设计直接检验恢复对固定BC的变化、以及v6下旧/新Full差异；它不包含新Full+v5或旧Full+v5的完整新确认交互，因此不能声称已验证所有控制器×世界模型交互。若确实需要该结论，应另扩设计，不能从缺失组推断。

确认不调参、不重选模型，保留全部失败。新独立确认的压力几何测试另列，不和原生成功率混算。开发未通过时不进入本步。
